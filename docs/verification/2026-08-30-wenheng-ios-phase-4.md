> 日期：2026-08-30
> 结论：严格监考第四阶段已完成本地实现、自动化回归、手机视口权限闸门验收、iOS 原生构建和模拟器冷启动；尚未执行生产迁移、真实人脸引擎联调、真机传感器测试、TestFlight 或 App Store 提交。

## 已实现能力

- 每场考试显式选择“普通考试”或“严格监考”，默认关闭监考；旧的全局基础防作弊设置不能隐式开启摄像头。
- 严格监考在用户阅读告知并分别确认监考数据处理和人脸核验之前，不创建同意凭证、不创建会话，也不请求摄像头或麦克风权限。
- 同意凭证绑定用户、考试、`attemptId`、数据区域、政策版本、告知版本、政策摘要和采集类别；过期、撤回或范围不一致时服务端拒绝。
- iOS 原生 `WenhengProctoringPlugin` 使用 AVFoundation 管理前置摄像头与麦克风采集轨道，使用 Vision 检测人数和基础光线状态。
- 麦克风只验证授权、设备和采集轨道是否持续可用，不读取、分析、保存或上传声音样本。
- 身份核验只在内存中保留最多 3 帧 JPEG，并在用户明确操作后提交；服务端只保存结果、原因、相似度、活体结果和模型，不保存原始画面。
- 客户端只上报白名单客观事件和有限状态字段；严重度、会话状态和是否人工复核由服务端决定，旧的任意消息接口已关闭。
- 网络、后台、摄像头、麦克风或屏幕采集异常会暂停作答；持续中断或长时间心跳缺失会由服务端进入人工复核，不会静默降级或由客户端直接判定作弊。
- 未成年人默认不能参加严格人脸监考；只有考试显式允许且存在有效的专项监护人同意时，服务端才允许创建会话。
- 中英文摄像头和麦克风用途说明已加入应用包，隐私清单声明照片或视频和敏感信息（生物特征），且声明不用于跟踪。

## 手机端权限闸门验收

在 393×852 手机视口用可控媒体权限和模拟考试 API 验证：

1. 普通考试完成加载后，摄像头/麦克风请求次数为 0，且不显示严格监考告知。
2. 严格监考显示用途、数据去向、事件留存和画面留存说明；用户确认前媒体权限请求、同意 API 和会话 API 调用次数均为 0。
3. 用户分别确认监考和人脸核验后，服务端先创建与本次 `attemptId` 绑定的同意凭证和会话，随后只发起一次媒体权限请求。
4. 模拟拒绝权限后，页面保持作答与交卷锁定，显示“打开系统设置”“重新检查”和“退出考试”，没有静默降级。
5. 全链路控制台错误为 0。

结果截图：`/tmp/wenheng-mobile-exam-phase4-permission-denied.png`。

iOS 26.5 的 `simctl privacy` 支持撤销麦克风权限，但不提供摄像头服务项；因此摄像头拒绝后的完整原生系统弹窗与恢复路径必须在真机验收。手机页面层的双权限拒绝闭环已由上述可控端到端场景覆盖。

## App Store 审核判断

苹果当前要求摄像头、麦克风或用户活动记录获得明确同意并提供清晰可见的采集指示；隐私政策需要说明收集、用途、共享、留存、删除和撤回；敏感 API 必须有完整用途文案；支持注册的应用必须能在应用内发起账号删除。

本阶段实现已按这些技术要求完成“考前单独同意、只在严格考试申请权限、持续状态指示、最小采集、账号注销入口和隐私清单”基础。严格监考本身不构成必然拒审，但本地实现通过不代表苹果已批准；实际审核还会核对隐私政策、App Store Connect 隐私问卷、审核账号、样例严格考试、真实服务可用性、未成年人处理和各销售地区法律合规。
