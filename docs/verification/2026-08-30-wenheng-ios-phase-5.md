# 问衡 iOS 阶段五验证记录

> 日期：2026-08-31
> 结论：严格监考人工复核与申诉第五阶段已完成本地实现、自动化回归、393×852 手机端闭环验收和 iOS 通用模拟器构建；尚未执行数据库迁移、真实账号/真机/预发布/生产联调、TestFlight 或 App Store 操作。

## 已实现能力

- 严重监考事实、持续心跳或传感器超时、身份核验失败进入 `review_required` 时，会在同一事务内幂等创建一宗复核案件；原始监考事件、身份核验结果和会话证据不被复核操作更新或删除。
- 考务端提供区域和考试所有权受限的响应式案件队列、详情时间线、请求补充、排除异常、确认违规、申诉处理与单案 CSV 审计导出。
- 教师只能读取和处理自己创建考试的案件，管理员受当前服务数据区域限制；无权访问和不存在案件统一返回 404，避免跨区域、跨教师和跨考生探测。
- 考生端通过成绩结果中的可靠 `attemptId` 精确查询本人案件，不使用 `examId` 猜测作答；成绩与监考复核采用两个相互独立的状态轨道。
- 候选人详情只返回公开决定原因、可见消息和本人申诉状态，不暴露考务用户编号、内部备注、内部版本轨迹或申诉处理决定编号。
- 考生可以回应最新一条补充说明请求；确认违规后可在首次决定起 7 天内提交一次申诉，过期、重复申诉和不合法状态由服务端拒绝。
- 所有写操作携带规范 UUID、语义摘要和 `expectedVersion`；相同编号/相同内容安全重放，不同内容冲突，旧版本不会覆盖服务端新状态。
- 自由文本去除控制字符并限制为 1–1000 字符；决定和申诉原因使用服务端白名单枚举。
- CSV 使用 UTF-8 BOM 与 CRLF，转义引号和换行并阻断公式注入；不导出媒体、生物特征或凭据字段。
- “确认违规”只改变复核案件投影。复核服务仓储契约不提供成绩或账号写方法，并有自动化测试断言成绩和账号状态保持不变。

## 手机端闭环验收

在 393×852 手机视口使用完整 API 信封、脱敏候选人案件数据和最小原生安全会话桥接桩验证：

1. 成绩页同时显示“成绩”和“监考复核”两个独立区块，并使用当前结果的 `attemptId` 精确查询案件。
2. `information_requested` 案件提交补充说明时，先模拟服务端版本冲突；客户端刷新后使用最新版本和最新问题重试，没有覆盖服务端状态。
3. `decided/violation_confirmed` 案件在期限内可以申诉；首次请求模拟网络不确定失败，手动重试复用完全相同的申诉 UUID 和请求语义。
4. 成功后只出现一个唯一申诉编号，状态进入“申诉处理中”，不能重复提交。
5. 页面无横向溢出，操作按钮可见，浏览器控制台错误为 0。
