# 问衡移动端最终产品需求

> 状态：需求已确认，进入分阶段实施
> 目标平台：iOS 优先，架构需允许后续扩展 Android
> 最近确认：2026-08-30

## 1. 问题定义

现有系统已经具备考试、练习、成绩、错题、监考和组织权限等 Web 能力，也完成了考生端移动 Web 基础，但尚未形成可在 iPhone 真机稳定运行、满足 App Store 规则、能够长期运营的最终手机产品。

最终产品需要让个人学习者与学校、企业考生在同一个“问衡”App 中完成注册或加入机构、接收任务、参加考试、恢复未完成答卷、查看成绩和持续学习；教师与管理员继续以 Web 后台为主要工作端。

## 2. 核心用户

### 2.1 个人用户

- 可自行注册、登录和注销账号。
- 可使用个人题库、练习、错题、收藏、学习进度和公开测评。
- 个人数据默认不属于任何机构。

### 2.2 学校或企业用户

- 使用机构预先分配的账号，或通过邀请加入机构。
- 可接收机构考试、培训任务、通知和成绩反馈。
- 机构考试、监考记录与组织权限由服务端控制。

### 2.3 教师与管理员

- 首个正式版本继续使用现有 Web 后台。
- iOS 首版不复制复杂的出题、组卷、组织管理和审批后台。

## 3. 已确认的产品边界

- 同一个 App 同时支持个人注册用户与学校、企业账号。
- 账户、组织成员关系和数据归属必须分离，不能用两套互不兼容的 App 或账号体系。
- iOS 优先；Android 属于后续平台扩展，不阻塞 iOS 首发。
- 首发最低系统版本为 iOS 16，覆盖常见尺寸的 iPhone，并以同一功能集兼容 iPad。
- 考试默认使用竖屏；仅在题型展示或监考规则确有需要时受控支持横屏，旋转过程不得导致答题状态或监考会话丢失。
- 首发发行范围同时覆盖中国大陆与海外地区，采用同一个 App、同一个 Bundle ID 和一致的核心产品体验，不拆成两个品牌或两套互不兼容的客户端。
- iOS Bundle ID 固定为 `top.qisw.wenheng`。
- App Store 首发版本对个人用户免费，不提供应用内购买，也不放置引导用户前往外部购买数字权益的入口。
- 架构预留个人会员和权益模型；只有在免费版本验证成立后，才新增 StoreKit 订阅、恢复购买、订阅管理和服务端交易校验。
- App Store 首发支持摄像头、麦克风和人脸核验的严格监考，但只对明确配置为严格监考的考试启用，不把敏感权限作为整个 App 的启动前置条件。
- “最终可用”包括真机稳定性、原生权限、隐私合规、账号注销、生产环境、TestFlight 和 App Store 提交准备，不以 WebView 能打开作为完成标准。

## 4. 数据与租户原则

- 用户是全局身份，机构成员关系是独立关联；一个用户可不属于机构，也可按授权加入一个或多个机构。
- 个人练习数据归个人；机构任务、答卷、成绩和监考记录必须带机构上下文。
- 切换机构或退出机构时，不得泄漏其他机构的数据，也不能删除用户的个人学习数据。
- 账号注销需要区分可立即删除的数据、需等待删除的数据和依法或因考试审计需要保留的数据，并向用户明确说明。

## 5. 当前已知缺口

- 尚无 Capacitor/iOS/Xcode 工程。
- 尚无 Keychain 安全令牌、APNs 推送、原生网络状态和 App 生命周期恢复。
- 尚无应用内账号注销闭环。
- 尚无 `PrivacyInfo.xcprivacy`、权限用途说明、App Store 隐私申报清单。
- 尚未完成摄像头、麦克风、人脸和监考数据在 iOS 真机上的完整授权与降级策略。
- 尚无 TestFlight、生产接口切换、崩溃监控和发布回滚流程。

## 5.1 已具备的发行基础

- 已确认当前 Apple Developer 会员实体类型为个人，账户可用于开发、真机测试、TestFlight 和 App Store 提交；以该主体公开发行时，商店销售者名称将显示账户持有人的个人法定姓名。
- 已有其他 App 办理 APP 备案的实际经验，域名备案等大陆互联网服务基础手续也曾办理。
- 当前信息倾向于个人主体；“问衡”的 App 名称、Bundle ID、服务域名和运营主体仍需单独核对或办理对应备案，不能把其他 App 的备案号直接视为本项目已备案。

## 6. 待确认决策

- “问衡”对应的 APP 备案新增或变更路径，以及最终使用的境内运营主体。

## 7. 商业化边界

### 7.1 首发版本

- 个人注册、公开测评和基础学习能力免费。
- 机构客户沿用组织采购或授权模式，App 只验证用户已有的机构权限，不在 App 内销售机构服务。
- 不接 StoreKit、不展示会员价格、不提供外部购买按钮或购买暗示。

### 7.2 后续会员阶段

- 会员权益通过服务端统一的 entitlement 模型表达，避免业务页面直接判断支付渠道。
- iOS 个人数字权益使用 StoreKit，并支持恢复购买、订阅状态同步、退款或撤销后的权益回收。
- 机构授权和个人会员并存时，权益取并集；退出机构不会误删个人购买权益。

## 8. 完成定义草案

最终版本至少需要满足：

- 个人注册与机构账号均能在真机完成完整考生流程。
- 冷启动、切后台、弱网、断网、系统杀进程后，已加载考试的答案不会静默丢失。
- 令牌存储、权限请求、账号注销和隐私说明符合 iOS 与 App Store 要求。
- 摄像头、麦克风或通知权限被拒绝时有明确解释和可执行的降级路径。
- 通过真实生产 API 的端到端测试、TestFlight 真机矩阵和提交前合规检查。
- 教师与管理员现有 Web 工作流不因移动端引入而退化。

## 9. 严格监考与敏感权限边界

### 9.1 首发能力

- 进入严格监考考试前，先展示监考项目、采集目的、数据去向、保留期限和退出后果，再分别申请摄像头和麦克风权限。
- 摄像头用于身份核验、人脸在场、多人、遮挡、光线和画面中断检测。
- 麦克风首发只检查授权、设备可用性和采集轨道中断，不默认录制、保存或上传音频内容。
- 身份核验只采集完成核验所需的有限人脸快照或特征；不得持续上传完整摄像头视频。
- 考试期间必须持续显示清晰的“监考中”状态，并说明当前启用的传感器。
- 普通考试、学习和个人中心不请求摄像头或麦克风权限；权限请求不得出现在 App 冷启动阶段。

### 9.2 拒绝与异常处理

- 普通考试可以在拒绝摄像头或麦克风后继续。
- 严格监考考试在权限不足时不得静默降级；应明确说明缺少的权限，并提供进入系统设置或退出考试的选择。
- 来电、切后台、权限被撤销、摄像头被其他应用占用和系统杀进程均形成可审计事件，但系统权限弹窗本身不计为违规切屏。
- 服务端决定考试是否可以恢复、继续或需人工复核，客户端不能自行把异常判定为作弊。

### 9.3 数据最小化与删除

- 默认上传监考事件和必要的身份核验结果，不上传连续音视频。
- 如机构未来需要完整录像，应作为单独的高风险企业能力重新评审，不纳入 App Store 首发默认范围。
- 隐私政策、App Store 隐私标签和应用内说明必须披露人脸等生物识别信息、照片或视频、标识符和诊断数据的实际处理方式。
- 人脸凭据、核验快照和监考事件分别定义保存期限、访问角色、导出审计和删除流程。

### 9.4 审核准备

- 提供可用的审核账号、演示考试和无需真实机构配合即可完整体验的监考流程。
- 审核备注逐项解释摄像头、麦克风和人脸用途，并说明不会进行后台或静默录制。
- `Info.plist` 权限用途文案必须具体说明采集内容和使用目的。

## 10. 中国大陆与海外发行架构

### 10.1 产品与客户端

- 使用一个 App Store 应用记录、一个 Bundle ID 和一套 iOS 客户端代码，按系统语言和账号所属区域提供简体中文、英文及对应隐私文本。
- 地区差异通过受控的服务端配置表达，包括 API 域名、对象存储、隐私政策、用户协议、监考开关、数据保留期限和客服入口；不得把关键合规边界写死在页面文案中。
- 用户注册时根据服务可用地区和明确告知确定数据区域；机构账号由机构租户预先绑定区域，客户端不能让用户任意切换数据驻留区。

### 10.2 数据边界

- 中国大陆用户和大陆机构的账号、答卷、人脸核验材料、监考事件及审计日志默认在中国大陆区域处理和存储。
- 海外用户和海外机构使用独立的海外服务区域；两个区域的数据库、对象存储、密钥、日志和运维权限必须可独立管理。
- 首发不做中国大陆与海外敏感个人信息的自动同步或混合分析。确需跨区域参加考试时，先完成数据流、告知与同意、个人信息保护影响评估及适用的数据出境合规评审，再开放对应租户。
- 账号目录如需支持跨区识别，只保存完成路由所需的最小化映射，不在全局目录复制人脸、答卷、监考快照或连续行为数据。

### 10.3 大陆发行门槛

- 中国大陆公开发行前，必须具备可核验的应用运营主体、有效的 Apple Developer 会员资料，以及与主体和应用信息一致的 APP/ICP 备案信息。
- 当前个人会员不阻塞开发和测试；若要以企业品牌作为商店销售者并承接学校、企业合同，应在正式公开发行前完成组织主体准备和 Apple Developer 会员迁移评估。
- 已确认开发和 TestFlight 阶段继续使用当前个人会员；正式公开上架前评估并推进组织主体及 Apple Developer 会员迁移，使商店销售者、备案、合同和敏感数据责任主体保持一致。
- App Store Connect 中的中国大陆合规信息、简体中文本地化、隐私政策、支持网址和备案元数据必须一致。
- 人脸等生物识别信息按敏感个人信息处理：仅在严格监考考试中基于明确目的和充分必要性采集，单独告知、单独同意，并落实权限控制、加密、留存和删除规则。
- 如产品实际数据流涉及个人信息出境，不能仅依赖“海外也能访问”这一产品设定推定合规，必须按当时适用规则单独评估并留存结论。

### 10.4 海外发行门槛

- 首发至少准备英文商店元数据、英文隐私政策与用户协议、海外支持联系方式和海外可访问的生产服务。
- 海外地区按实际销售国家或地区分批开放，不以“全球一次性全选”替代当地年龄、隐私、税务、消费者保护和生物识别规则检查。
- 严格监考仍遵守同一套最小采集原则；如某地区对人脸或未成年人数据要求更严格，应允许按地区或租户关闭该能力，而不影响普通考试使用。

## 11. 首发推送通知

- 使用 APNs 提供新考试或培训任务下发通知。
- 考试开始提醒默认在开考前 24 小时和 1 小时发送，机构可按考试配置提醒时间，用户可在系统设置中关闭非强制提醒。
- 成绩发布、人工复核结果、考试时间变更和考试取消属于首发业务通知。
- 异地登录、账号安全和隐私条款重大变化属于高优先级账号通知，并保留邮件等可审计的备用触达方式。
- 营销活动、会员促销和每日打卡不纳入首发推送，后续如启用必须单独取得通知授权并提供细分开关。
- 推送正文不得包含完整成绩、人脸核验结果、违规详情或其他敏感信息；锁屏通知只展示完成操作所需的最少内容，点击后在 App 内鉴权查看详情。

## 12. 统一账号与合并规则

- 用户使用稳定的全局用户标识，邮箱、E.164 国际手机号、用户名、Apple 登录等作为可绑定和解除绑定的登录身份，不再把邮箱本身当作不可变用户主键。
- 机构邀请命中已验证邮箱或手机号时，只为现有用户新增机构成员关系，不创建重复用户，也不覆盖个人学习数据。
- 机构预建账号由用户通过验证码、邀请凭证或强制修改临时密码完成认领；认领前不得访问敏感成绩或监考材料。
- 两个已存在账号需要合并时，用户必须分别完成两个账号的重新认证；合并操作生成审计记录，并保留考试、成绩、监考事件的原始创建者与租户归属。
- 不得依据姓名、昵称、相似邮箱、设备标识或人脸相似度自动合并账号。
- 中国大陆与海外账号不自动跨区域合并；跨区账户关联需要单独的数据流和合规评审。
- 现有仅支持中国大陆 11 位手机号的校验需要迁移为带国家或地区代码的 E.164 格式，同时保持大陆 `+86` 号码的便捷输入体验。

## 13. 首发登录与本机解锁

- 中国大陆个人用户支持手机号验证码和邮箱密码；机构用户支持机构账号、临时密码或邀请码认领。
- 海外个人用户支持邮箱密码、Sign in with Apple 和 Google 登录。
- GitHub 登录不进入手机端首发；现有 Web 端是否保留由后台产品范围另行决定。
- 自建人脸识别不用于手机端账号登录。用户完成正常登录后，可选择使用 iOS LocalAuthentication 提供的 Face ID 或设备密码解锁本机登录状态，App 不获取或保存系统 Face ID 生物特征。
- 严格监考中的人脸身份核验是独立的考试能力，不得与 Face ID 解锁、账号合并或营销画像复用数据。
- 支持应用内找回密码、绑定与解绑登录身份、重新认证和账号注销。
- 当 Google 等第三方登录可用时，同一地区同时提供 Sign in with Apple；第三方身份返回的邮箱隐藏或变化时，以 provider subject 等稳定标识绑定，不以邮箱字符串自动合并账号。

## 14. 未成年人保护

- 产品同时服务成年人和未成年人，但不将整个 App 定位或申报为 App Store 儿童类别。
- 注册只采集判断适用规则所需的年龄段，不默认收集完整出生日期；中国大陆未满 14 周岁用户不能独立完成个人注册。
- 未满 14 周岁用户需要监护人账号完成身份确认，并对儿童专门个人信息处理规则作出可撤回、可审计的同意。
- 学校预建或导入未成年人账号不能被视为自动取得人脸信息处理同意；产品提供监护人邀请、告知、同意状态和撤回记录闭环。
- 未成年人严格人脸监考默认关闭。只有监护人针对明确目的和处理范围完成单独同意后才能启用，并提供人工核验、线下监考或其他不依赖人脸信息的可执行替代方案。
- 不向未成年人投放广告，不使用儿童个人信息进行行为画像或营销推荐。
- 海外账号按数据区域和实际发行国家或地区应用相应年龄门槛、监护人同意及儿童数据规则，不用中国大陆年龄门槛覆盖所有地区。
- 监护人撤回同意后，停止后续非必要处理；依法或因考试审计需要暂时保留的数据进入限制处理状态，并明确保留依据和期限。

## 15. 移动端技术路线

- 采用“React 移动考生业务层 + Capacitor 原生容器 + Swift 关键原生模块”的混合原生架构，不采用只打开现有网站的简单 WebView 套壳。
- 普通任务、学习、成绩、错题和个人中心复用现有 React 领域逻辑，但使用独立的 App 导航、移动布局和触控交互，不直接暴露桌面后台页面。
- Keychain、APNs、LocalAuthentication、AVFoundation、网络状态、应用生命周期、本地加密存储和隐私相关能力由 iOS 原生层负责。
- 严格监考通过受限、类型明确的原生桥接接口向业务层提供授权状态、监考状态、必要快照和异常事件，Web 层不能任意访问原生传感器或文件。
- 答题会话和待同步操作写入本地加密存储；断网、切后台、系统终止进程后允许按服务端规则恢复，不能仅依赖页面内存或浏览器缓存。
- 教师与管理员继续使用现有 Web 后台；后续 Android 复用 React 业务层、API 契约和本地会话协议，并实现对应 Android 原生适配器。

## 16. 已确认的系统分层与数据流

- iOS App 分为 React 考生业务层、类型明确的原生桥接层、Swift 原生能力层，以及本地加密数据库和可靠同步队列。
- 服务端通过区域路由将请求发送至中国大陆区或海外区；两个区域分别管理数据库、对象存储、密钥和审计日志。
- 个人首次注册时明确选择国家或地区，系统语言和 IP 只能用于推荐；机构账号由机构或邀请码确定数据区域。
- 登录令牌存入 Keychain，React 页面只使用短期会话能力，不直接接触长期凭证。
- 任务和考试包下载到本地加密数据库；每次作答先原子保存到本地，再通过带幂等标识的队列同步。
- 严格监考由原生模块生成必要事件和有限快照；首发不持续上传完整音视频。
- 最终交卷结果以服务端为准，本地保存提交凭证、版本和同步状态，避免客户端假成功。
- 全局目录只保存完成账号区域路由所需的最小映射；教师和管理员后台不能跨区域混合查询敏感数据。

## 17. 已确认的考生端结构与流程

- 底部一级导航固定为首页、任务、学习和我的；教师或管理员桌面后台菜单不进入 iOS 考生端。
- 首次启动只进行品牌引导、地区选择和登录或注册，不在冷启动阶段申请摄像头、麦克风或通知权限。
- 个人用户可在注册后加入机构；机构预建账号完成认领后进入对应组织。多机构用户切换时，首页和考试详情始终显示当前机构。
- 考前准备包含考试包下载、服务端时间校准、网络与存储检查；严格监考额外完成隐私告知、权限检查、身份核验和设备测试。
- 答题页持续显示剩余时间、同步状态和监考状态；每次作答先写入本地，弱网时明确显示“已保存到本机，等待同步”。
- 来电、切后台、旋转、断网或系统终止进程后进入受控恢复流程；恢复资格和剩余时间由服务端规则决定。
- 交卷前检查未答题和同步状态，服务端确认后展示提交凭证；网络中断时显示“交卷处理中”，不得错误显示成功。
- 成绩页支持即时成绩、延迟发布和人工复核；机构可限制受保护试题进入个人错题、复制或导出。
- iPad 使用自适应分栏但不复制业务功能；支持动态字体、VoiceOver、足够触控区域、明暗模式和非颜色单一表达。
- 推送深链在重新认证后继续到原目标页面，不因登录过期丢失跳转上下文。

## 18. 已确认的可靠性、监考与安全设计

- 普通考试按考试策略支持必须在线或允许短时离线；严格监考必须联网开始并维持心跳，超过离线宽限期后进入受控暂停或待复核。
- 答案事件携带考试尝试标识、递增序号、版本和校验值，服务端使用幂等规则确认；重复上传不得产生重复答案或覆盖较新版本。
- 进程被系统终止后使用原考试尝试恢复，并由服务端返回允许继续、已提交、已过期或待人工处理状态。
- 计时使用服务端时间锚点和设备单调时钟，修改系统时间不能延长考试。
- 交卷请求使用唯一幂等标识；超时后查询提交状态，不重复创建答卷，也不提前显示成功。
- 原生监考状态分为准备、正常、降级、中断和结束。异常只记录客观事件，客户端不自行判定作弊。
- 严格监考传感器异常时显示原因、宽限时间和处理方式；是否继续、暂停或复核由服务端策略决定。
- 长期凭证存入 Keychain，本地考试数据加密并排除普通设备备份，敏感文件使用 iOS 文件保护能力。
- App 进入后台时遮盖考试内容；截屏或录屏只做可实现的检测、提示和审计，不承诺系统无法保证的绝对禁止。
- 日志和崩溃报告默认脱敏，不记录令牌、完整答案、人脸图片、麦克风内容或未成年人身份信息，不接入广告追踪或 IDFA。
- 注销立即撤销凭证；依法或因考试审计暂时保留的数据进入限制处理，到期自动删除。
- 所有错误界面必须说明发生了什么、答案是否安全以及用户下一步可以做什么。

## 19. 已确认的测试、发布与验收标准

- 真机矩阵覆盖最小屏 iPhone、主流和最大尺寸 iPhone、代表性 iPad，以及 iOS 16、仍受支持的中间版本和提交时最新正式版。
- 场景矩阵覆盖个人、机构、多机构、未成年人、监护人、大陆、海外、普通在线、短时离线、严格监考、弱网、断网、网络切换、来电、锁屏、杀进程、旋转、系统时间变化、低电量和低存储。
- React 单元与组件测试、API 契约与区域隔离测试、Swift 原生模块测试、模拟器端到端测试、真机故障注入、隐私与无障碍检查共同构成发布门槛。
- 注册、登录、加入机构、下载考试、作答、恢复、交卷和注销等关键流程在发布候选版本中必须全部通过，不允许存在未关闭的 P0 或 P1 缺陷。
- 重复执行断网、杀进程和交卷超时场景时，答案静默丢失次数必须为 0；本地作答保存反馈目标为 300 毫秒以内。
- TestFlight 试点达到足够样本后，无崩溃会话目标不低于 99.5%。
- 隐私清单、权限说明、隐私标签、隐私政策、用户协议、账号注销、数据保留表、大陆备案材料、英文发行材料和 Apple 审核演示流程全部完成后，方可提交审核。
- 发布依次经过本地真机、TestFlight 内部测试、大陆与海外封闭试点、提交前审计、App Store 审核和分阶段开放。
- 构建、签名、上传、审核回复和公开发布在实际执行前分别取得操作确认；已上传、等待审核、审核通过和已经公开必须严格区分。
