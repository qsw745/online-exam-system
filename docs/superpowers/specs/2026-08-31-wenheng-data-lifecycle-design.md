# 问衡数据生命周期与账号删除闭环设计

> 日期：2026-08-31
> 状态：已确认
> 前置规格：`docs/superpowers/specs/2026-08-30-wenheng-mobile-product-design.md`
> 前置实现：`docs/verification/2026-08-30-wenheng-ios-phase-5.md`

## 1. 目标

建立可执行、可恢复、可审计的数据生命周期闭环，使问衡能够真实完成账号注销、到期数据清理、必要考试档案匿名化、合法保留冻结和删除回执，而不把“提交申请”“禁用账号”或“前端隐藏”误写成已经删除。

本阶段需要同时满足以下产品目标：

- 用户可在 App 内选择立即删除或 30 天后删除，并持续查看处理状态。
- 账号注销后删除直接身份信息和非必要关联数据；仍需保留的考试档案与原账号不可逆解绑。
- 人脸凭据、监考事件、复核案件、考试档案、日志和备份分别执行明确期限，不使用一个最长周期覆盖所有数据。
- 到期任务由区域内独立 Worker 自动执行；只有有依据、有范围、有期限的保留冻结可以暂停相应类别。
- Worker 崩溃、重复调度、网络中断或数据库短暂故障不能造成漏删、误删或虚假完成。
- 新增用户关联表如果没有声明生命周期处理方式，自动化检查必须失败。

## 2. 非目标与边界

本阶段不包含：

- 执行预发布或生产数据库迁移。
- 删除任何真实用户、真实考试、真实监考或生产备份数据。
- 配置真实生产邮件、对象存储、告警平台或密钥管理服务。
- 替代运营主体或法律顾问确定法定保留期限、争议期限和各发行地区义务。
- StoreKit、会员订阅、营销推送、TestFlight 或 App Store 提交。
- 将所有历史表一次性重构成全新的身份模型；只改造完成本阶段闭环必需的用户关联表和访问路径。

本地完成只表示代码、迁移、Worker、界面和自动化验证通过，不代表生产数据已经被清理。

## 3. 依据与设计原则

1. Apple 要求支持账号创建的 App 在 App 内提供完整账号删除，并删除开发者无合法义务继续保留的关联数据；异步完成可以接受，但必须明确预计时间并告知结果。
2. 中国现行个人信息规则要求账号注销后删除个人信息或进行匿名化；法定期限未届满或技术上难以删除时，只能继续存储并采取必要保护，不能继续用于普通业务。
3. 人脸信息保存期限不得超过实现处理目的所必需的最短时间；处理影响评估和必要合规记录使用独立期限，不能据此延长原始人脸信息。
4. 海外默认遵守目的限制、数据最小化和存储期限限制；正式开放具体国家或地区时再叠加当地规则。
5. 删除、匿名化、隔离保留和删除回执是四种不同结果，接口、状态和用户文案必须明确区分。
6. 删除任务以区域数据库为事实来源；Redis 可以用于唤醒，不保存最终完成结论。
7. 不执行运行时猜测式清表。每一类用户关联数据必须使用显式、经过测试的处理器。

## 4. 已确认产品决策

### 4.1 双路径注销

- `IMMEDIATE`：用户二次确认后立即冻结账号并进入执行队列，不可取消，目标 24 小时内完成。
- `GRACE_PERIOD`：账号立即冻结，计划时间为申请后 30 天；Worker 开始不可逆步骤前允许重新认证并取消。
- 两种模式都撤销全部在线会话，并禁止登录、考试、学习、机构操作和后台访问。
- 30 天宽限不是继续使用期；宽限期间除查询状态、取消申请和必要安全处理外不继续处理账号数据。

### 4.2 匿名考试档案

- 删除姓名、邮箱、手机号、用户名、头像、登录身份、人脸凭据、个人设置、收藏、错题和非必要学习数据。
- 需要保留的成绩、答卷与必要考试审计迁移至随机匿名主体，不继续引用 `users.id`。
- 匿名主体不保存原用户映射，不参与排行榜、推荐、营销、用户画像或跨产品分析。
- 教师和管理员界面统一显示“已注销考生”，只能在原考试权限范围内查看必要档案。
- 期限到达后继续自动删除匿名考试档案。

### 4.3 分层期限与策略固化

- 平台定义期限安全上下限；区域策略和机构策略只能在允许范围内收紧或选择。
- 创建数据或生命周期任务时固化适用策略版本与 `retainUntil`。
- 后续配置变化不能静默延长既有数据期限。
- 延长保留只能通过合法冻结，必须记录范围、理由、依据、创建人、到期时间和审计事件。

### 4.4 首发默认期限

| 数据类别 | 默认期限 |
| --- | --- |
| 人脸凭据模板 | 账号有效期间；撤回同意或注销执行时立即删除 |
| 身份核验原始画面 | 0 天，继续不落库 |
| 身份核验结果、监考事件 | 考试结束后 180 天 |
| 人工复核决定、消息、申诉 | 180 天，或案件关闭后 30 天，取较晚者 |
| 个人公开考试成绩与答卷 | 365 天；注销后立即匿名化 |
| 机构考试成绩与答卷 | 默认 3 年，可在 1–5 年范围配置；注销后立即匿名化 |
| 注销执行回执、合规审计记录 | 去身份化后 3 年 |
| 普通运行日志 | 180 天，敏感字段先去除或脱敏 |
| 备份中的已删除数据 | 最长 30 天自然淘汰；恢复时重放删除清单 |

以上为产品安全基线，不替代各地区或机构的最终法律判断。

### 4.5 自动执行与合法冻结

- 到期任务自动执行，不要求管理员逐个审批。
- 合法冻结只能针对明确的数据类别、资源范围和期限。
- 冻结不能阻止无保留依据的人脸凭据、会话凭据或无关数据删除。
- 冻结到期后任务自动重新入队；延期必须再次填写依据并生成审计。
- 系统提供全局暂停和安全预演，但不得用来日常拖延账号删除。

### 4.6 用户通知

- 申请后在 App 内显示请求编号、模式、预计完成时间和状态，并向已验证邮箱发送回执。
- 30 天方案在到期前 7 天和 24 小时提醒，并提供取消入口。
- 完成、延期或存在依法隔离保留时发送最小化回执。
- 注销通知不使用 APNs 锁屏通知。
- 待发送地址和消息体进入加密事务消息箱；成功发送或最多 7 天后清理。

## 5. 总体架构

处理链路：

`注销申请或期限扫描 → 账号冻结/策略解析 → 生命周期账本 → 独立 Worker → 数据处理器 → 回执/消息箱/删除墓碑`

### 5.1 `LifecyclePolicyResolver`

职责：

- 读取平台、区域、机构和资源级策略。
- 验证配置是否落在平台安全边界内。
- 计算删除、匿名化或隔离保留结果，以及不可静默修改的 `retainUntil`。
- 生成规范化策略快照与摘要，供任务重放和审计。

策略解析器是纯领域组件，不执行 SQL 或发送通知。

### 5.2 `LifecycleLedger`

MySQL 区域数据库保存请求、步骤、租约、冻结、回执和消息箱。账本是生命周期任务的唯一事实来源；API 响应、管理界面和 Worker 都读取同一状态。

### 5.3 `LifecycleWorker`

Worker 作为独立 Node.js 进程运行：

- 通过数据库租约认领任务，防止多实例同时处理同一请求。
- 每个处理器独立事务、小批量提交并保存游标。
- 租约超时后允许其他 Worker 接管。
- 支持 `dry-run`、正常执行、全局暂停、指数退避和人工恢复。
- Redis 只可作为低延迟唤醒机制；Redis 丢失不影响数据库中的待处理任务。

### 5.4 显式数据处理器注册表

每个用户关联数据集必须注册为以下一种：

- `DELETE`：物理删除。
- `ANONYMIZE`：迁移至不可逆匿名主体或去除直接、间接标识。
- `RESTRICTED_RETENTION`：存在有效依据时只读隔离保存，到期后删除。
- `NO_SUBJECT_DATA`：经过审查确认不含用户关联数据。

处理器固定表名和 SQL 模板，参数只接受已验证的主体编号、游标和批量大小。运行时请求不能提供表名或列名。

构建期清单测试覆盖当前数据库中所有用户外键和已知身份字段；新增未分类数据集会阻断测试。

### 5.5 删除墓碑与备份保护

删除完成时生成不可逆主体指纹：

- 使用区域密钥执行带版本的 HMAC，不保存原邮箱、手机号、`public_id` 或 `users.id`。
- 清单保存的是删除时对稳定公开主体编号计算出的指纹；恢复旧备份时，重放器对恢复出的公开主体编号使用对应密钥版本重新计算并匹配。
- 删除清单通过 `DeletionManifestSink` 写入不随主业务备份回滚的独立存储。
- 旧备份恢复后必须先运行墓碑重放命令，再允许区域服务对外开放。
- 本地实现只提供接口、测试适配器和可重复重放命令；真实独立存储及恢复演练属于预发布基础设施验收。

## 6. 数据模型

### 6.1 扩展 `account_deletion_requests`

保留现有请求表作为父账本，新增：

| 字段 | 说明 |
| --- | --- |
| `deletion_mode` | `IMMEDIATE` 或 `GRACE_PERIOD` |
| `execution_status` | 生命周期状态机 |
| `request_digest` | 请求幂等摘要 |
| `policy_version` | 固化策略版本 |
| `policy_snapshot_json` | 当时适用的数据类别与期限，不含凭据 |
| `status_token_digest` | 只读状态凭证摘要，不保存原始令牌 |
| `started_at` | Worker 开始不可逆执行时间 |
| `next_attempt_at` | 下次重试时间 |
| `last_error_code` | 稳定错误码，不保存敏感错误正文 |
| `restricted_retention_until` | 仍有隔离数据时的最晚期限 |

同时把现有 `user_id` 改为可空外键并采用 `ON DELETE SET NULL`。Worker 在执行完成前依靠该字段定位主体；所有数据处理器成功后删除 `users`，由数据库置空该字段。迁移不得把它改为级联删除，否则删除父账号会一并破坏步骤、回执和状态查询。

已有 `PENDING/CANCELLED/COMPLETED` 数据在迁移时映射到新状态，不执行历史删除。完成清理时还要清空确认词等不再需要的申请输入，只保留请求编号、区域、无身份策略摘要、状态、时间和统计信息。

### 6.2 `data_lifecycle_steps`

每个注销请求或期限扫描与处理器对应一条或多条步骤记录，核心字段包括：

- `step_id`、可空的 `request_id`、可空的 `scan_run_id`、`step_code`。
- 数据库约束保证 `request_id` 与 `scan_run_id` 恰好一个非空，并分别建立 `父记录 + step_code` 唯一键。
- `status`、`cursor_json`、`planned_count`、`processed_count`、`attempt_count`。
- `lease_owner`、`lease_expires_at`、`next_attempt_at`。
- `started_at`、`completed_at`、`last_error_code`。

游标只保存稳定主键边界，不保存被删除内容。

### 6.3 `data_retention_holds`

核心字段：

- `hold_id`、`data_region`、`scope_type`、`scope_id`、`category_code`。
- `reason_code`、`legal_basis_reference`、`created_by`、`created_at`、`expires_at`。
- `released_by`、`released_at`、`release_reason`。

数据库约束要求 `expires_at` 非空且晚于 `created_at`。应用层限制允许期限和可冻结类别。

### 6.4 `anonymous_exam_subjects`

只保存随机 `anonymous_subject_id`、`data_region`、档案类型和创建时间，不保存原用户映射。需要保留的 `exam_results`、监考和复核记录新增可空的 `anonymous_subject_id`，并在匿名化成功后清空 `user_id`。

答卷优先通过 `exam_result_id` 关联匿名成绩记录；历史冗余 `answer_records.user_id` 在迁移后清空或删除，不作为匿名档案身份键。

任何持久记录在注销完成后都不能同时包含原用户标识和 `anonymous_subject_id`；注销请求、删除回执和墓碑也不得保存匿名主体编号。

### 6.5 `data_deletion_receipts`

保存请求编号、区域、完成类型、各类别处理数量、策略摘要和完成时间。不得保存邮箱、手机号、姓名、人脸数据、匿名主体编号、完整成绩、答卷或监考详情。

### 6.6 `data_deletion_tombstones`

保存带密钥版本的不可逆主体指纹、区域、请求编号、完成时间和清单同步状态。墓碑不能用于登录、找回账号或关联匿名考试档案。

### 6.7 `transactional_outbox`

保存最小化消息类型、加密收件地址、加密载荷、发送状态、尝试次数、下次尝试和最迟清理时间。消息投递器与生命周期 Worker 分离，避免外部邮件失败回滚已经完成的数据处理。

### 6.8 `data_retention_policies`

保存版本化平台、区域和机构策略。平台安全上下限不可由普通管理员修改；机构策略只能在区域允许范围内选择。策略更新只影响新数据和新任务。

### 6.9 `data_retention_scan_runs`

保存系统期限扫描编号、区域、策略版本、数据类别、扫描时间窗口、状态、租约、游标和聚合数量，不保存用户身份或被清理内容。扫描使用确定性的 `区域 + 类别 + 时间窗口` 唯一键，重复调度只能继续同一次扫描；账号注销步骤与期限扫描步骤共用 Worker 和处理器，但父记录严格分离。

## 7. 状态机

主状态：

`REQUESTED → SCHEDULED → RUNNING → COMPLETED`

异常和终态：

- `HELD`：至少一个必要步骤被有效冻结，其他无关步骤继续执行。
- `RETRYING`：发生可恢复错误并等待下次尝试。
- `ATTENTION_REQUIRED`：达到重试上限或发现未分类数据，需要修复原因后恢复。
- `COMPLETED_WITH_RESTRICTED_RETENTION`：账号与可删除数据已经处理，仍有依法隔离保存的数据。
- `CANCELLED`：仅 30 天模式且不可逆执行开始前允许进入。

主状态由步骤状态推导，不能由管理接口直接写成完成。

## 8. 执行顺序与处理规则

### 8.1 接收请求

1. 验证认证用户、当前密码或等价近期认证凭据、完整确认词和规范 UUID 请求编号。
2. 检查同一用户是否已有有效请求；相同编号和相同语义返回原结果，不同语义返回冲突。
3. 在同一事务中冻结账号、撤销数据库会话、保存策略快照、创建步骤和申请回执消息。
4. 事务提交后尽力撤销 Redis 会话；数据库账号状态仍是最终访问闸门。

### 8.2 处理顺序

1. 删除人脸凭据、OAuth 凭据、刷新令牌、密码重置令牌和设备令牌。
2. 删除头像、资料、设置、收藏、错题、非必要学习数据和私有内容。
3. 删除用户生成内容，或在确有上下文完整性需要时替换为无身份占位内容。
4. 将仍需保留的成绩、答卷和必要考试审计迁移到匿名主体。
5. 删除已到期限的监考、身份核验和复核数据；未到期限或被冻结的数据去标识并隔离。
6. 解除机构成员、角色、任务分配、排行榜和推荐关系。
7. 对必须保留的安全日志移除直接标识和不必要的间接标识。
8. 生成删除墓碑所需的主体指纹，删除 `users` 记录并确认注销请求中的 `user_id` 已置空，再生成删除回执和完成通知。

删除 `users` 必须是最后一个不可逆业务步骤。任何前置处理器未完成时不能删除父账号或标记完成。

步骤 8 完成后执行关联性断言：业务库、回执、墓碑和消息箱中不存在能够把原用户身份重新连接到匿名考试主体的字段组合；断言失败时进入 `ATTENTION_REQUIRED`，不得报告完成。

### 8.3 常规期限扫描

Worker 每天按索引扫描到期记录，为监考、复核、匿名考试档案、日志、回执和消息箱生成或继续执行清理步骤。扫描器只选择 `retainUntil <= now` 且没有有效冻结的记录。

## 9. API 与权限

### 9.1 用户 API

在现有 `/account/deletion/*` 路径上兼容扩展：

- `GET /account/deletion/preview`：返回两种模式、数据分类、预计时间和确认词。
- `POST /account/deletion/request`：新增 `requestId`、`mode` 和客户端生成的 32 字节高熵 `statusToken`，返回请求状态并只在本次申请流程中展示该令牌。
- `POST /account/deletion/status`：优先接受 `requestId + statusToken`；兼容执行前的邮箱密码查询。
- `POST /account/deletion/cancel`：只接受 30 天模式、执行前状态和重新认证。

客户端必须在首次请求前生成并暂存原始状态令牌；网络结果不确定时，相同请求编号、模式和令牌原样重试。服务端验证令牌强度后只保存摘要，不能生成或恢复明文。iOS 通过现有安全会话能力写入 Keychain；Web 只保存在当前注销状态会话，不写普通 `localStorage`。

### 9.2 管理 API

新增区域隔离的 `/privacy/lifecycle` 资源：

- 列表和详情只返回状态、步骤代码、数量、错误码和时间。
- 安全预演返回按数据类别聚合的数量，不返回记录内容。
- 冻结创建、解除和延期使用独立权限与 UUID 幂等键。
- 全局暂停属于最高权限操作，必须记录原因和自动复核时间。
- 不提供标记完成、跳过步骤、读取已删除数据或输入任意 SQL 的接口。

权限拆分：

- `privacy:lifecycle:read`
- `privacy:lifecycle:dry-run`
- `privacy:lifecycle:hold`
- `privacy:lifecycle:pause`

管理员仍受当前服务 `data_region` 限制，不能跨区域查询请求、冻结或统计。

## 10. 用户与管理界面

### 10.1 用户注销页

- 使用两个清晰选项展示立即删除与 30 天后删除。
- 二次确认前展示删除、匿名化和条件保留类别。
- 长表单适配 375×667、393×852、安全区和键盘滚动。
- 30 天状态页显示剩余时间和取消入口。
- 立即删除确认后明确不可撤销，并显示目标处理时间。
- 状态页不显示内部表名、监考细节、管理员身份或冻结依据全文。

### 10.2 管理控制台

- 展示各区域待处理、运行中、冻结、重试、需要关注和完成数量。
- 单个任务只展示步骤、计划数量、处理数量、重试次数和稳定错误码。
- 冻结表单强制选择类别、原因、依据和到期时间。
- 提供预演、暂停和恢复，但不提供强制完成。

## 11. 错误处理、并发与恢复

- 使用原子认领或行锁加租约，保证同一任务同一时刻只有一个 Worker。
- 每个步骤独立事务，默认小批量处理；批量大小由受控配置钳制。
- 步骤开始前和提交后都可以安全崩溃；重放依靠唯一键、游标和目标状态判断。
- 可恢复错误指数退避，达到上限进入 `ATTENTION_REQUIRED` 并触发无敏感内容告警。
- 账号在失败期间保持冻结；任务失败不能恢复登录或业务访问。
- 合法冻结只暂停对应处理器；无关步骤继续执行。
- 邮件发送失败不回滚数据删除，由消息箱独立重试。
- 所有日志使用请求编号、步骤代码、数量和错误码，不记录原始个人数据。

稳定错误码至少包括：

- `LIFECYCLE_REQUEST_CONFLICT`
- `LIFECYCLE_ALREADY_IRREVERSIBLE`
- `LIFECYCLE_UNCLASSIFIED_DATASET`
- `LIFECYCLE_LEASE_CONFLICT`
- `LIFECYCLE_HOLD_ACTIVE`
- `LIFECYCLE_POLICY_OUT_OF_RANGE`
- `LIFECYCLE_STEP_RETRY_EXHAUSTED`
- `LIFECYCLE_STATUS_TOKEN_INVALID`

## 12. 通知与隐私

- 申请、宽限提醒、取消、完成和延期使用事务消息箱。
- 邮件正文不包含完整成绩、人脸核验、违规原因、组织内部信息或管理员姓名。
- `COMPLETED_WITH_RESTRICTED_RETENTION` 只告知保留类别、一般原因和预计期限，不披露调查或安全细节。
- 加密收件信息在发送成功后立即清理；失败消息最多保留 7 天。
- 完成回执的去身份化审计版本保留 3 年，但不能用于联系或重新识别用户。

## 13. 测试设计

### 13.1 领域与服务测试

- 两种注销模式、确认词、幂等摘要、取消边界和状态转换。
- 平台、区域、机构策略优先级、上下限和逐条期限固化。
- 冻结范围、期限、解除、延期和过期自动恢复。
- 匿名主体不含原账号映射，匿名成绩不进入排行榜或推荐。
- 相同请求重放返回原结果，不同语义返回冲突。

### 13.2 Worker 故障注入

- 在每个步骤的事务提交前后模拟崩溃。
- 两个 Worker 并发认领同一任务。
- 租约过期后安全接管。
- 数据库短暂失败、消息投递失败和墓碑同步失败。
- 重复执行删除、匿名化、回执和通知步骤。
- 达到重试上限后进入需要关注状态，修复后从检查点恢复。

### 13.3 数据覆盖与隐私测试

- 当前所有用户外键、邮箱、手机号、身份标识和用户生成内容表都有明确处理分类。
- 新增未分类数据集时测试失败。
- 回执、日志、管理 API 和消息体不包含禁止字段。
- 合法冻结不能扩大到未选择的数据类别。
- “确认完成”必须以所有必要步骤的真实终态为依据。

### 13.4 数据库与备份场景

- 迁移只导入验证 `up/down`，本地阶段不连接生产数据库。
- 隔离测试数据库验证完整注销、常规期限扫描、小批量游标和事务回滚。
- 使用旧快照夹具模拟恢复，再重放删除墓碑，确认账号和关联数据不会重新出现。
- 安全预演数量与正式执行数量一致。

### 13.5 客户端与 iOS 验收

- 375×667 和 393×852 两种视口。
- 立即删除、30 天删除、取消、网络中断、杀进程和状态凭证恢复。
- 已完成账号无法登录；匿名成绩不显示个人身份。
- 意外应用控制台错误为 0；主动模拟断网产生的浏览器资源诊断必须单独精确断言，Web/后端测试、类型检查和构建通过。
- Capacitor 同步与 iOS 无签名通用模拟器构建通过，主程序包含 `x86_64 arm64`。

## 14. 运行与可观测性

Worker 指标只包含聚合信息：

- 各状态任务数和最老任务年龄。
- 每个处理器成功、重试、失败和处理行数。
- 租约占用、过期接管和单步耗时。
- 消息箱待发送数量与最老消息年龄。
- 墓碑待同步数量和恢复重放结果。

告警不得包含邮箱、手机号、姓名、人脸信息、成绩、答卷或监考详情。

生产启用前必须具备：独立 Worker 进程、单区域数据库连接、区域密钥、消息投递器、删除清单独立存储、监控告警和运行手册。本地实现不能替代这些基础设施验收。

## 15. 迁移与发布顺序

1. 新增阶段六迁移，建立策略、步骤、期限扫描、冻结、匿名主体、回执、墓碑和消息箱结构，并扩展注销请求表及必要用户外键。
2. 迁移只增加结构和兼容状态映射，不自动处理历史真实用户。
3. 部署支持新结构的 API 与暂停状态 Worker。
4. 在隔离或预发布数据库运行数据覆盖清单和安全预演。
5. 验证匿名化、删除、墓碑重放、邮件回执和回滚预案。
6. 经单独确认后在预发布启用 Worker，再根据证据决定生产迁移和启用。

本阶段代码实施期间不得执行第 4 步之后的任何外部操作。
