# 问衡考生端移动化基础设计

## 1. 目标

在不重写现有后端、不影响教师与管理员桌面工作流的前提下，把现有在线考试系统升级为“问衡”品牌，并交付一个可作为后续 iOS 原生壳基础的移动优先考生端。

本阶段完成后，考生应能在 375–430 像素宽的手机浏览器中顺畅完成登录、查看任务、进入考试、持续保存答案、提交试卷、查看成绩和错题；教师与管理员继续使用现有 Web 后台。

## 2. 已确认的产品决策

- 用户品牌统一为“问衡”，定位为“AI 智能测评与学习平台”。
- 品牌口号为“以问见知，以衡见长”。
- 考生端优先移动化；教师端、管理员端本阶段不做完整手机重构。
- 继续复用现有 React 前端、Express API、MySQL 数据和权限体系。
- iOS 采用“移动优先 React 页面 + Capacitor 原生能力”的路线，但 Capacitor/Xcode 工程放在下一阶段；本阶段先建立稳定的移动 Web 基础。
- 不把 WebView 包装视为上架完成；后续 iOS 阶段必须增加原生安全存储、通知、权限和网络恢复能力。

## 3. 本阶段范围

### 3.1 品牌基础

- 新增单一品牌配置模块，提供名称、短名称、副标题、口号和页面标题格式。
- 浏览器标题、登录页、页头、邮件模板和可见的“在线考试系统”文案改为引用品牌配置或统一品牌文案。
- 内部仓库名、数据库名、API 路径和 Java 包名保持不变，避免无业务收益的大范围重命名。
- 更新 Web 图标和主题色元数据，为下一阶段生成 iOS 图标保留稳定的视觉母版。

### 3.2 考生端移动导航

- 手机端主导航固定为四个一级入口：`首页`、`任务`、`学习`、`我的`。
- 首页承载今日任务、进行中考试、最近成绩和通知摘要。
- 学习入口聚合题库练习、收藏、错题与学习进度。
- 管理员、教师继续使用现有侧栏；手机底部导航只在考生角色且非考试页显示。
- 考试页保持沉浸式独立布局，不显示侧栏、页签、AI 浮窗或底部导航。

### 3.3 手机布局修复

- 全局内容区在小于 768 像素时使用 12–16 像素安全边距，并适配 `env(safe-area-inset-*)`。
- 清除考生高频页面中的固定最小宽度，表格在手机端改为卡片或可读的纵向信息组。
- 登录、首页、我的任务、考试、结果详情、练习、错题和个人中心作为首批适配页面。
- 所有主要触控目标最小可点击区域为 44×44 像素。
- 所有新交互提供可见键盘焦点，并尊重 `prefers-reduced-motion`。

### 3.4 考试答案可靠性

- 新建独立的考试草稿模块，不依赖 React 组件即可测试。
- 草稿按 `用户 ID + 任务 ID + 考试 ID` 隔离，采用带版本号的数据结构。
- 每次答案变更后最多 500 毫秒写入本地草稿，不再等待固定 8 秒轮询。
- 页面启动时，如果服务端仍允许作答且本地草稿与当前考试匹配，则自动恢复答案和标记题。
- 成功提交后清除对应草稿；提交失败时保留草稿并展示明确的重试入口。
- 监听在线状态：离线时显示“答案已保存在本机”，恢复联网后允许用户重新提交。
- 倒计时以服务端截止时间为准，不能因页面刷新而重置。
- 本阶段不承诺真正离线启动一场新考试；只保证已加载考试的本地答题保护和恢复。

### 3.5 质量基础

- 为前端引入 Vitest 与 Testing Library，测试纯逻辑、Hook 和关键移动组件。
- 第一批测试覆盖品牌配置、草稿版本校验、草稿隔离、恢复、提交后清理、手机导航可见规则。
- 保持前端、后端 TypeScript 类型检查和生产构建通过。
- 不在本阶段补齐全项目历史功能的测试覆盖率。

## 4. 架构与边界

### 4.1 新增模块

`apps/web/src/shared/config/brand.ts`

- 唯一的前端品牌配置源。
- 导出 `brand` 常量和 `formatDocumentTitle(pageTitle?)`。

`apps/web/src/features/exams/draft/examDraft.ts`

- 定义草稿数据结构、存储键、解析、保存、读取和清除函数。
- 仅依赖 `Storage` 接口，测试可使用内存实现，不直接耦合浏览器全局对象。

`apps/web/src/features/exams/hooks/useExamDraft.ts`

- 连接考试页状态与草稿模块。
- 管理延迟写入、启动恢复和提交后清理。

`apps/web/src/shared/components/MobileStudentNav.tsx`

- 根据角色、路由和考试状态显示四入口底部导航。
- 只负责导航呈现，不请求业务数据。

`apps/web/src/shared/styles/mobile-foundation.css`

- 集中定义安全区、移动内容边距、底部导航占位和触控尺寸。

### 4.2 现有模块改造

- `Layout.tsx`：接入考生底部导航，考试页继续使用独立布局。
- `ExamPage.tsx`：接入 `useExamDraft` 和在线状态提示；不继续复制旧 `useExamRunner` 的状态实现。
- `QuestionPracticePage.tsx`：移除 1200 像素最小宽度，手机端使用单列内容。
- 登录、仪表盘、任务、结果、错题和个人中心页面：只做考生主流程必需的响应式修改。
- 邮件服务：可见品牌文案改为“问衡”，内部链接和业务逻辑不变。

### 4.3 数据流

1. 考生打开考试页，前端从 API 获取考试、服务端截止时间和题目。
2. 前端用用户、任务、考试标识读取本地草稿。
3. 草稿版本、标识和考试状态有效时恢复答案；无效草稿被忽略并清除。
4. 每次作答更新 React 状态，并在 500 毫秒内写入本地存储。
5. 提交时发送当前内存答案；成功后清草稿并跳转成绩页。
6. 网络失败时不跳转、不清草稿，页面保留重试按钮和本机保存状态。

## 5. 视觉方向

### 5.1 主题

“可信的测量仪器”：界面应让正式考试显得可靠、安静、精确，同时让日常学习保持轻盈，不使用传统教务系统常见的大面积政务蓝。

### 5.2 色彩

- 墨衡蓝 `#10233F`：标题、导航和正式考试状态。
- 青玉绿 `#18A77B`：主要操作、已完成和安全状态。
- 刻度金 `#D9A441`：倒计时、标记题和需要注意的信息。
- 纸白 `#F7F9FC`：主背景。
- 云灰 `#E7ECF3`：分隔与禁用状态。
- 警示朱 `#D94A4A`：违规、失败和危险操作。

### 5.3 字体与排版

- 中文正文使用系统字体栈，确保 iOS 清晰度和加载性能。
- 品牌字标使用有收放感的定制字距，不额外下载大体积中文字体。
- 倒计时、题号和成绩数字使用等宽数字特性，体现“刻度”感。

### 5.4 布局签名

品牌识别元素是“衡尺”：由一条细轴、两端刻度和中心问号负形构成。它只用于 Logo、进度和关键分隔，其他界面保持克制。

手机首页结构：

```text
┌─────────────────────┐
│ 问衡          消息 头像 │
│ 今天，先完成最重要的一件事 │
├─────────────────────┤
│ 进行中的考试 / 倒计时     │
├─────────────────────┤
│ 今日任务卡片              │
│ 最近成绩与薄弱点          │
├─────────────────────┤
│ 首页   任务   学习   我的  │
└─────────────────────┘
```

## 6. 错误与边界处理

- 本地存储不可用：继续允许答题，但显示“当前设备无法保存本地草稿”。
- 草稿 JSON 损坏或版本不兼容：忽略并清除，不阻断考试加载。
- 用户切换账号：因存储键包含用户 ID，不恢复其他账号草稿。
- 考试已提交或已截止：不恢复草稿，按照服务端状态进入结果页或结束页。
- 提交超时或断网：保留答案，显示本机保存时间和“重新提交”。
- 摄像头或麦克风拒绝授权：沿用当前监考策略，由考试配置决定是否允许继续；不把系统权限弹窗本身计为切屏违规。

## 7. 验收标准

- 375、390、430、768 和 1024 像素视口下，考生主流程不存在页面级横向滚动。
- 考生手机端可以通过四入口底部导航完成主流程；考试页不显示底部导航。
- 刷新考试页后能恢复同一用户、同一考试的答案和标记题。
- 断网后继续作答不会丢失已加载题目的答案；恢复联网后可以重新提交。
- 成功交卷后对应本地草稿被删除，提交失败时草稿保留。
- 页面、登录界面和邮件中的用户可见产品名统一为“问衡”。
- 新增测试全部通过，前后端类型检查与生产构建通过。

## 8. 非目标

- 本阶段不创建 Xcode/Capacitor 工程，不提交 App Store。
- 不实现 APNs、Keychain、通过 Apple 登录、账号注销和隐私清单；这些属于 iOS 上架阶段。
- 不重构教师和管理员的复杂表格、流程设计器及系统管理页面。
- 不改变后端数据库结构、API 路径或现有角色模型。
- 不承诺在 iOS 上阻止用户切换 App；只记录可验证的前后台事件。

## 9. 后续阶段

第一阶段验收后，第二阶段创建 Capacitor iOS 工程，接入原生安全存储、摄像头/麦克风权限、网络状态、推送通知、通过 Apple 登录、账号注销、隐私清单和 App Store 元数据；第三阶段完成真机矩阵、TestFlight 与商店审核准备。
